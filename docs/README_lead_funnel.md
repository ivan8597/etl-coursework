# Lead, Simulator и SalesFunnel

Скрипт `lead_funnel.py` реализует три модели из задания.

## Модели

`Lead` хранит `lead_id`, `datetime`, `page`, `form_title`, `contacts`, `name` и текущий этап `current_stage`. Метод `to_dict()` возвращает данные лида для отправки в CRM.

`Simulator` хранит `simulator_type` и `version`. Метод `to_dict()` возвращает словарь с этими полями.

`SalesFunnel` хранит список уникальных этапов. Этапы можно передать при создании или добавить позже через `add_stage(stage_name)`. Повторяющийся этап вызывает `ValueError`.

## Обработка лида

Один вызов `process_lead(lead)` обрабатывает только один этап. При первом вызове выбирается первый этап, затем лид отправляется в CRM через `requests.post`. В тело запроса передаётся словарь из `lead.to_dict()`.

При HTTP-статусе `200` добавляется сообщение об успешной отправке. Любой другой статус или сетевое исключение приводит к сообщению об ошибке. После отправки лид перемещается на следующий этап. Если этап был последним, добавляется сообщение о достижении конца воронки.

Текущий этап хранится в `lead.current_stage`. Повторный вызов после последнего этапа возвращает сообщение о завершении и не отправляет лид повторно.

Пустая воронка вызывает `ValueError`. В URL CRM по умолчанию используется адрес из задания, но его можно заменить в конструкторе, что удобно для тестов:

```python
funnel = SalesFunnel(["Новая заявка", "Квалификация"], crm_url="https://example.test/crm")
```

## Запуск

Установите библиотеку `requests`, если она ещё не установлена:

```bash
pip install requests
```

Запуск демонстрации:

```bash
python lead_funnel.py
```

Проверка без реальных запросов в CRM:

```bash
python test_lead_funnel.py
```

Тесты заменяют `requests.post` mock-объектом и проверяют успешный ответ, ошибочный HTTP-статус, сетевое исключение, переходы по этапам, дубликаты этапов и пустую воронку.
